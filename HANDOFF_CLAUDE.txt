3. TEST SUITE REPAIR: ALL ROOT CAUSES & EXACT FIXES (Exhaustive)
--------------------------------------------------------------------------------
Initial State:
  Suite failed during collection on 8 test files with:
  "ImportError: cannot import name 'openai_client' from 'services.ai_providers' (unknown location)"
  Followed by collection abortion due to module-level SystemExit in test files.

Root Cause A: "unknown location" on services.ai_providers / services.ai_usage
  - File: tests/test_broadcast_market.py
  - Mechanism: Lines 50-56 created raw types.ModuleType("services.ai_providers") and
    assigned them into sys.modules without __file__. When pytest collected subsequent
    test files that legitimately imported services.ai_providers, Python found the stub
    in sys.modules lacking __file__, raising ImportError (unknown location).
  - Fix: Wrapped the import in a try...finally block in test_broadcast_market.py that
    restores the original sys.modules references immediately after import.

Root Cause B: Pytest INTERNALERROR from module-level sys.exit
  - Files: test_v11_voice_integration.py, test_learning_model.py,
           test_response_functions.py, test_voice_model_led.py
  - Mechanism: Module-level sys.exit(...) calls executed during pytest collection.
    SystemExit escaping collection caused pytest to fail with INTERNALERROR.
  - Fix: Converted to:
      if __name__ == "__main__":
          sys.exit(...)
      else:
          raise AssertionError(...)

Root Cause C: .pytest_cache Access Denied on Windows
  - Mechanism: .pytest_cache had restricted Windows ACLs from another user / elevated process.
  - Fix: Added `addopts = -p no:cacheprovider` to pytest.ini. Pytest now runs cleanly without
    attempting to write to .pytest_cache.

Root Cause D: Model Bump Desync in test_daily_blog.py (Line 363 & 703)
  - File: tests/test_daily_blog.py
  - Mechanism: services/ai_providers._GEMINI_LLM had been bumped from "gemini-3.6-flash" to
    "gemini-3.8-flash". The test mock flaky() hardcoded `if model != "gemini-3.6-flash"`,
    and line 703 expected "gemini-3.6-flash" in writer_models().
  - Fix: Replaced hardcoded "gemini-3.6-flash" with db._gemini_default(), ensuring tests
    track the system's configured default Gemini model dynamically.

Root Cause E: Cross-Test Monkey-Patching Leaks in routes.realtime_gemini (11 Failures)
  - Files: tests/test_gemini_free_trial.py & tests/test_v11_voice_integration.py
  - Mechanism: Both files patched routes.realtime_gemini (rtg.voice_interviewer_mode = lambda: "renderer"
    and rtg._resolve_live_model = lambda: "fake-live") without saving or restoring module state.
    When test_voice_model_led.py ran later, it inherited the stale "renderer" mode and "fake-live"
    resolver, failing 11 Gemini live assertions.
  - Fix: Added save & restore blocks in both test files to restore all patched attributes on
    routes.realtime_gemini to their original state upon completion.
