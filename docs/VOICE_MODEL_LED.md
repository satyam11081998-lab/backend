# Model-led realtime voice interviewer

Date: 2026-10-01. Switch: `VOICE_INTERVIEWER` (default `renderer` = today's flow, unchanged).

## Why

In the current realtime flow the speech model (`gpt-realtime-2.1`, the ChatGPT-voice family) is
only a voice: auto-responses are off, every candidate turn goes to the backend
(`/voice-decision`), rule code picks a function, a text model writes a line, and the voice reads
it word for word. That costs 1–2 s per turn, loses tone and pauses, and replaces the model's
judgement with keyword rules.

Model-led mode lets the speech model hold the conversation itself and moves the backend
**beside** the call instead of in front of it.

## How it works

| Piece | Where | What it does |
|---|---|---|
| Playbook | `prompts/voice_interviewer_playbook.py` | MECE's teaching approach in plain words + the case (never the solution): decide length from the moment; understand meaning (no question mark needed); say "you're on track" briefly and specifically; at most one question, often none; reasonable assumptions stand; never refuse help; answers only via `answer_request`. |
| Session | `routes/realtime.py` | For a model-led user: playbook instructions, `create_response: true` (the model answers by itself), barge-in kept, tools `get_hint` and `answer_request`. Response carries `interviewer: "model_led"`. |
| Coach | `POST /attempts/{id}/voice-coach` → `services/voice_coach.coach_notes` | After each saved candidate turn the browser asks the coach; the existing learner-state code (session_signals) reads stuck / frustrated / asked for help / asked for the answer / interviewer over-questioning / clarifications used up / progressing, and the notes are pushed into the live session with `session.update` (only when they change). |
| Hint ladder | `POST /attempts/{id}/voice-tool` `get_hint` | cue → hint → framework or analogy → one partial step; frustration skips the gentle cue. Generated by `gpt-4o-mini` (`VOICE_COACH_MODEL`) from the case, the stored hint and the transcript; any sentence carrying the solution's final number is removed; generic fallback if the model is unavailable. |
| Answer rule | `POST /attempts/{id}/voice-tool` `answer_request` | 1st ask (any stage): no answer — "I'd recommend thinking along these lines… the full worked answer is on your results page" + a framework/analogy. Asking again (`VOICE_ANSWER_AFTER_ASKS`, default 2): the worked answer, after an honest note that their results will show they got this part from the interviewer. |
| Live guardrail | frontend `lib/voice/model-led.ts` | While the interviewer is speaking, if it starts stating a final answer with a number (or "here's the full solution") before the answer is allowed, the reply is cut (`response.cancel` + `output_audio_buffer.clear`) and steered back to a framework. |

Kept unchanged: transcript saving (`/realtime-turn`, same rows for scoring), C9 clarification
counting, credits/metering, scoring and the results page, the learner state (`hint_level` is kept
in step for the debrief). The session state for this mode lives under
`attempts.session_state.voice` (`hint_level`, `answer_requests`, `answer_revealed`, `coach_notes`).

Behaviour differences to know:
- If sincerely asked, the voice interviewer says it is MECE's AI interviewer (the text prompt
  still tells the model to present as human).
- Coach notes apply from the next turn (the model has already answered the current one).
- Only the OpenAI realtime transport (`voice_mode: realtime` in public-config). Gemini and the
  pipeline are unchanged.

## Switch it on

Render (backend) environment, then restart:

```
VOICE_INTERVIEWER=allowlist
VOICE_INTERVIEWER_ALLOWLIST=<your login email>
```

Everyone else keeps today's flow. `VOICE_INTERVIEWER=model_led` turns it on for everyone;
`renderer` (or unset) turns it off — no deploy needed either way. Optional:
`VOICE_ANSWER_AFTER_ASKS` (default 2), `VOICE_COACH_MODEL` (default gpt-4o-mini).
